## 文档结构约定

每个分类文档统一采用三步结构，便于 Agent 快速抽取并引用：

```
## 问题描述
（现象描述、触发场景、典型特征、现场信息收集项）

## 根因分析
（按可能性排序的根因列表，每个根因标注来源案例/DTS编号、定位手段）

## 解决措施
（**可执行动作序列**：按阶段0基线→阶段N修复→验证闭环，每步含动作类型/命令/UI路径/预期输出/通过标准/失败回退。详见各分类文档。）
```

## 动作类型约定（agent可直接执行/指引执行）

解决措施中的每个动作标注动作类型，agent据此判断执行方式：

| 动作类型 | 含义 | agent执行方式 |
|---|---|---|
| `CMD:ofdm pktstart` / `CMD:ofdm pktinfo` / `CMD:ofdm pktstop` | OFDM Shell命令，可直接执行 | agent通过设备Shell直接执行，解析输出JSON判断通过/失败 |
| `CMD:setfreq` | 设置频段Shell命令，可直接执行 | agent通过CCO Shell执行，解析输出判断 |
| `ACT:web` | 数采WEB UI操作 | agent给出精确UI路径，指引现场人员执行（或通过数采API若可用） |
| `ACT:app` | SUN2000APP操作 | agent给出精确UI路径，指引现场人员近端执行 |
| `ACT:log` | 日志解析 | agent指引搜索关键词，或解析现场提供的日志 |
| `ACT:hso` | HSO软件+抄控宝诊断 | agent指引现场人员连接并获取数据 |
| `ACT:physical` | 现场物理操作 | agent给出排查清单，指引现场人员执行并反馈 |
| `ACT:upgrade` | 软件升级 | agent指引升级到修复版本，升级后验证 |

**命令规格**：所有 `CMD:` 命令的完整规格（参数/预期输出/通过标准/失败回退）见 [09-诊断工具与命令](./09-诊断工具与命令.md)。

## Agent执行流程

```
用户问题输入
    ↓
1. 检索本README"快速定界决策表" → 定位分类文档
    ↓
2. 读取分类文档"问题描述" → 收集现场信息（AskUserQuestion补全缺失项）
    ↓
3. 执行"阶段0：建立基线"（CMD:ofdm / ACT:log）→ 记录基线B0
    ↓
4. 读取"根因分析" → 按可能性排序定位根因
    ↓
5. 按对应"阶段N"执行动作序列：
    ├─ CMD: 命令 → 解析输出 → 判断通过/失败
    ├─ ACT:web/app/physical/upgrade → 给现场精确步骤 → 等待反馈
    └─ 每步失败 → 按"失败回退"列进入下一措施
    ↓
6. 执行验证动作（CMD:ofdm pktinfo）→ 对比基线B0判断修复是否成功
    ↓
7. 通过 → 闭环输出（根因/动作序列/对比表/后续建议）
   失败 → 回退到下一根因或下一阶段，重试
```

**关键原则**：
- **强制顺序**：先诊断建立基线 → 再修复 → 后验证。禁止跳过基线直接调整（否则无法判断修复效果）。
- **每个修复动作后必须验证**：用 `CMD:ofdm pktinfo` 对比基线B0，不能仅凭命令返回成功就判定修复完成（已知缺陷DTS2025041903467：setfreq返回成功但实际未生效）。
- **失败回退**：每个动作的"失败回退"列指明下一步，agent按此自动进入下一措施。

## 排查总流程（MBUS通讯故障"5个规定动作"）

来自《逆变器MBUS通讯故障_X板斧V1.0》，任何 PLC 通信问题排查均建议按此顺序，对应动作类型：

1. **动作1：站点信息收集**（`ACT:log`+AskUserQuestion）— 子阵数/机型/版本/MBUS版本/箱变类型/双分裂/PID/电表N线/线缆类型/距离/故障现象/频段功率防串扰
2. **动作2：物理连接排查**（`ACT:physical`）— 线序（ABC三相）、开关（箱变低压/刀熔/通讯柜空开）、连接（AC线缆/接地）
3. **动作3：日志排查**（`ACT:log`）— 数采 `run_log.log` 搜 MFT(丢包率)/STA NUM(组网)/EQ O(在线离线)；操作日志解析 `usrmg_user_log.db`
4. **动作4：配置排查**（`ACT:web`+`ACT:app`）— 逆变器(SUN2000APP: MBUS使能/并机通讯参数)、数采WEB(内置MBUS使能/防串扰使能/组网使能/功率10/频段0.7-2.3M)
5. **动作5：抄控宝接入CCO**（`ACT:hso`）— HSO软件查看组网拓扑、信噪比、衰减（前三步未定位根因时执行）

## 使用建议

- Agent 在回答用户问题前，应先对照"快速定界决策表"定位分类，再读取对应分类文档。
- 每个根因尽量标注来源（DTS编号/案例文件/幻灯片页码），便于追溯。
- 频段调整是"粗调"，AI参数调优是"细调"——建议先做频段/配置调整，再叠加AI调优。
- 避免跳步：必须先完成信息收集和日志分析（阶段0基线），确认根因后再调整配置。
- 修复后必须用 `CMD:ofdm pktinfo` 验证，对比基线B0判断是否真正修复。
