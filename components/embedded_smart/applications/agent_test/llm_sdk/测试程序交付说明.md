# 测试程序交付说明（llm_sdk + wifi_test）

> 交付对象：OpenHarmony 小型系统 HiSpark AI Camera（Hi3516DV300，产品 `ipcamera_hispark_taurus`，LiteOS-A）
> 目标：拿到这两个文件夹后，放置 → 改 2 处配置 → 编译烧录 → 板上跑通"连 WiFi + 问大模型"。

---

## 一、这两个文件夹是什么

### applications/llm_sdk（SDK 库 + 交互测试台）
| 文件 | 作用 |
|---|---|
| `llm_client.c/.h` | LLM 直连库源码（mbedTLS 443 连云端网关，消息≤1KB，回复缓冲 4KB） |
| `wifi_client.c/.h` | WiFi 连接库源码（写 wpa 配置、fork 守护、等 IP、查 IP） |
| `wifi_wpa.c` | wpa_supplicant 守护进程源码（编译为 /bin/wifi_wpa） |
| `libllmclient.a/.so`、`libwificlient.a/.so` | 预编译库（BUILD.gn 链接的是 .a） |
| `llm_test.c` | 交互式串口测试台（wifi/relay/gw/uart 全指令，不带参数时运行） |
| `customer_test.c` | 原交付示例（保留） |
| `BUILD.gn`、`bundle.json` | 构建定义（编译出 wifi_wpa / customer_test / llm_test） |
| `README.md` | SDK 接口说明 |
| `build_*.sh` | 单独交叉编译脚本（可不用） |

### applications/wifi_test（新写测试套件，3 个程序）
| 文件 | 编译产物 | 用途 |
|---|---|---|
| `wifi_test.c` | `/bin/wifi_test` | 一键自动：连热点→问 LLM→持续监控掉线报警（**死循环占用 shell**） |
| `wifi_cli.c` | `/bin/wifi_cli` | WiFi 一次性命令（apx/connect/wait/status），**推荐** |
| `llm_ask.c` | `/bin/llm_ask` | LLM 一次性问答（ASCII / uni 中文码点 / hex 三种模式），**推荐** |
| `串口测试指令手册.md` | — | 板上指令速查（同时有根目录副本） |

一次性命令（wifi_cli / llm_ask）**不读串口输入**，参数全由 shell 传递，绕开了 LiteOS shell 与用户程序抢控制台输入的所有坑，日常测试优先用它们。

## 二、放置位置

两个文件夹**原样拷贝**到 OpenHarmony 源码树的 `applications/` 下（与 `applications/sample` 并列）：

```
<源码根>/
├── applications/
│   ├── llm_sdk/        ← 整个文件夹
│   ├── wifi_test/      ← 整个文件夹
│   └── sample/ ...
├── vendor/hisilicon/hispark_taurus/...   ← 需要改（见下）
└── ...
```

- 可选清理：llm_sdk 里的 `customer_test`、`llm_test`、`wifi_test` 三个旧编译产物（可执行文件）不参与构建，删不删都行。

## 三、必做修改（共 3 处）

### 1. 注册组件（必须，否则不编译）
`vendor/hisilicon/hispark_taurus/config.json` 找到 `"subsystem": "applications"` 段，在 components 数组里加两行（JSON 不能写注释，注意上一行结尾逗号）：

```json
        "components": [
          { "component": "camera_sample_app", "features":[] },
          { "component": "camera_screensaver_app", "features":[] },
          { "component": "llm_sdk", "features":[] },
          { "component": "wifi_test", "features":[] }
        ]
```

组件名必须与两个 `bundle.json` 里的 `component.name` 完全一致。

### 2. 改热点账号（必须）
`applications/wifi_test/wifi_test.c` 文件头配置区：

```c
#define WIFI_SSID "123456"       ← 改成自己的热点
#define WIFI_PSK  "20010504"     ← 改成自己的密码
```

### 3. 改 API key（必须，换成自己的 key）
key 独立写在两个文件里，都要改：

| 文件 | 位置 | 影响的程序 |
|---|---|---|
| `applications/wifi_test/llm_ask.c` | 顶部 `GW_KEY` | `/bin/llm_ask`（一次性问答） |
| `applications/wifi_test/wifi_test.c` | 配置区 `GW_KEY` | `/bin/wifi_test`（自动模式） |

`/bin/llm_test`（交互模式）key 不内置，运行时用 `gw set key sk-xxx` 设置。

网关默认值（如换服务商同步改）：
```c
#define GW_IP    "47.102.215.139"
#define GW_VHOST "api.siliconflow.cn"
#define GW_PORT  443
#define GW_MODEL "deepseek-ai/DeepSeek-V4-Flash"
```

### 4.（可选，推荐）停掉串口刷屏服务
`vendor/hisilicon/hispark_taurus/init_configs/init_liteos_a_3516dv300.cfg` 的 `"init"` 段删掉这三行，可消除 `05700/CommSdk: server not init` 周期性刷屏：

```
"start softbus_server",
"start devattest_service",
"start dslm_server",
```

## 四、编译与烧录

```bash
cd <源码根>
export PATH=$HOME/.local/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

# 首次（或换产品）才需要 set：
python3 build/hb/hb set -p ipcamera_hispark_taurus --root $(pwd)

# 编译（增量约 3 分钟）
python3 build/hb/hb build

# 核对产物（rootfs/bin 下应有 6 个文件）
ls out/hispark_taurus/ipcamera_hispark_taurus/rootfs/bin/ | grep -E "wifi|llm"
# 期望: wifi_test  wifi_cli  llm_ask  llm_test  customer_test  wifi_wpa

# 拷贝烧录镜像（内核没改，只烧 rootfs）
cp out/hispark_taurus/ipcamera_hispark_taurus/rootfs_vfat.img <烧录目录>/
```

环境前提（全新机器）：`repo sync` 后先拉 Git-LFS 大文件（`repo forall -c "git lfs install --force; git lfs pull"`），prebuilts 工具链就绪，hb 已安装 —— 详细流程见仓库内《交付包集成指南.md》。

## 五、板上验证（串口）

烧录上电，等 `OHOS #` 提示符（约 1 分钟）：

```
exec /bin/wifi_cli apx 123456 20010504      ← 连热点(改成自己的)
exec /bin/wifi_cli wait 30                  ← 等拿 IP
exec /bin/wifi_cli status                   ← 确认在线(打印 wlan0 = x.x.x.x)
exec /bin/llm_ask uni 4f60 597d             ← 问 LLM："你好"(uni=Unicode码点模式)
exec /bin/llm_ask hello                     ← 英文直接问
```

- 中文提问用 uni 模式：任意"中文转Unicode"工具转成 4 位码点，每个码点一个参数（串口终端发不了中文字节，这是最稳的办法）。速查表见《串口测试指令手册.md》。
- 回复格式：`[llm] << reply(n): 正文`；失败 `FAIL 负数 (人话原因)`。

## 六、接手人需要知道的机制

1. **WiFi 链路**：`wifi_connect_ap` 写 `/storage/wpa_supplicant.conf` → fork 起守护 `/bin/wifi_wpa`（走 HDF WiFi 驱动）→ DHCP 拿 IP。守护随系统常驻，断电重开机后需重新执行 `apx` + `wait`。
2. **LLM 链路**：`libllmclient.a` 用 mbedTLS 直连网关 443 端口（网关必须是 **IP**，域名放 `vhost` 做 SNI），消息上限约 1KB，回复缓冲 4KB。
3. **控制台抢占**：`llm_test` 交互模式会挂起 shell 独占输入（退出时恢复）；如果交互模式回显异常/字节错乱，不要纠结，直接用一次性命令。
4. **wifi_test 自动模式**是死循环（掉线报警监控用），会一直占用 shell，期间无法执行其它命令。
5. `build/lite/components/` 下的组件注册表**不需要**改，lite 构建按 `bundle.json` 自动扫描。

## 七、常见坑速查

| 现象 | 处理 |
|---|---|
| 编译报 component 未找到 | 核对 config.json 组件名与 bundle.json 的 `component.name` 一字不差 |
| 链接报 `libXXX.a: unknown directive: version` | Git-LFS 没拉，见第四节环境前提 |
| `mkfs.vfat: command not found` | PATH 缺 `/usr/sbin`，照第四节写死 PATH |
| 中文发出去板上没反应 | 串口终端发不了中文 → 用 `llm_ask uni` |
| `llm_ask` FAIL -1 | WiFi 没连上，先 `wifi_cli status` |
| FAIL -4 | key 失效/额度用完，换 key 重编 |
| FAIL -3 | 网关 90 秒无响应，重试 |
| 05700/CommSdk 刷屏 | 第三节第 4 步没做 |
