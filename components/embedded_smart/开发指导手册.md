# embedded_smart 组件包 · 移植与开发指导手册（最小树 / 完整树）

> 面向拿到 `embedded_smart` 包、要在 **3516（Hi3516DV300）OpenHarmony 小系统环境**里完成移植、
> 然后日常开发与编译的工程师。支持两种目标环境：
> **① liteos_m_branch 最小系统树**（摘出的最小树,无 liteos-a 源码,内核靠本包 Core_SDK 重链）、
> **② 3516 完整系统树**（repo 全量,liteos-a 源码齐全）。
> 流程：环境对号 → 移植五步 → 编译 → 找产物 → 功能开发 → 内核 → 烧录。
> 所有命令均在 **WSL Ubuntu 22.04**（或原生 Ubuntu）中执行；`<树根>` 指环境树根目录。

---

## 0. 快速开始（熟手 30 秒版）

```bash
# 前提:已有一套 3516 小系统环境树(最小树或完整树,见 §1.1)+ prebuilts(§3),包已在合法位置(§4)
cd <树根>
ls kernel/liteos_m/components/embedded_smart/Core_SDK/SDK/build_kernel.sh   # 包在位
hb set -p ipcamera_hispark_taurus    # 选产品,只需一次
hb build                              # 全量约 10 分钟,末尾 build success
```

新环境或中途报错 → 从 §1 顺序往下读。

## 1. 先读懂三件事（避免迷路）

1. **内核镜像从哪来,取决于你在哪种环境**（对照表见 §1.1）:
   - **最小树**:树内没有 liteos-a C 源码,`kernel/liteos_a_stub/` 只是桩,hb build 时经
     `stub_link.py` 调用**本包** `Core_SDK/SDK/build_kernel.sh`,把官方 1230 个内核 .o
     重链成 `OHOS_Image.bin`（恒为 6578176 字节,与官方镜像逐字节一致）
     ——**Core_SDK 必须随包,且包路径不可移动**（§4）;
   - **完整树**:liteos_a 内核源码齐全,内核照常源码编译,**用不到 Core_SDK 与 liteos_a_stub**。
2. **功能代码的单一源在本包内**:`applications/agent_test/` 下平铺 7 个组件 SDK:
   pca9685_sdk、wake_sdk、app_test、key_sdk、llm_sdk、
   llm_stream、ui_display_sdk。两种环境都通过顶层 `applications/` 壳（bundle.json）→
   `vendor/.../config.json` 把 7 个组件挂进产品编译——**改代码只改本包,不用同步**。
   注意:壳与 vendor 里已无 build_test 组件（已随旧结构移除）。
3. **包内没有内核源码**,"改内核"分环境:最小树走 Core_SDK 重链（§7.1）;完整树直接改
   `kernel/liteos_a/` 源码正常重编（§7.2）。

反过来说:最小树编译报"找不到 `.../embedded_smart/Core_SDK/SDK/build_kernel.sh`" = 包还没移植好;
完整树编译报 agent_core 源文件缺失 = 没装 §2 要求的 device/soc agent 目录。

### 1.1 两种目标环境对照（先对号入座）

| | ① liteos_m_branch 最小系统树 | ② 3516 完整系统树（repo 全量） |
|---|---|---|
| 判定 | 有 `kernel/liteos_a_stub/`,无 `kernel/liteos_a/` 源码 | 有 `kernel/liteos_a/`（真实内核源码） |
| 内核来源 | Core_SDK 重链 1230 个官方 .o（恒 6578176B） | liteos_a 源码正常编译（尺寸随源码/配置） |
| Core_SDK / liteos_a_stub | **必需**（桩调 build_kernel.sh） | 不参与构建（闲置,仅回退镜像参考） |
| prebuilts 工具链 | 自备最小集约 2.5G（§3.3） | 建树时一般已下载,无需再备 |
| `device/soc/.../platform/agent` 目录 | 环境自带 | **默认没有,需向维护者索取**（§2/§4①） |
| 本包放置路径 | `kernel/liteos_m/components/embedded_smart`（写死） | 同左（kernel/liteos_m 是真实仓,包为其中未跟踪目录） |
| 改内核的方式 | Core_SDK 重链（§7.1） | 改 liteos_a 源码重新 hb build（§7.2） |
| repo/git 注意 | 不要 repo sync（§10） | 不要把本包提交进上游 kernel_liteos_m（§10） |

后续步骤两种环境基本一致,差异处均以「最小树」「完整树」标注。

## 2. 包内容地图（共约 70M）

`applications/agent_test/` 平铺 7 个组件 SDK:

| 路径（相对本包） | 是什么 | 开发者要动吗 |
|---|---|---|
| `applications/agent_test/pca9685_sdk/` | PCA9685 16 路 PWM 舵机 SDK（Otto 机器人动作） | **改这里** |
| `applications/agent_test/wake_sdk/` | 离线唤醒（Luna 词,microWakeWord+TFLM）+ 实时对话（WebSocket/TLS） | **改这里** |
| `applications/agent_test/llm_sdk/` | LLM 客户端 + WiFi 客户端库 + 独立测试程序 | **改这里** |
| `applications/agent_test/llm_stream/` | **v1.3 流式 LLM 库**（SSE 打字机 llm_chat_stream + 长消息 llm_chat_raw） | **改这里** |
| `applications/agent_test/key_sdk/` | GPIO 按键 SDK（HDF 用户态 GPIO HDI） | **改这里** |
| `applications/agent_test/ui_display_sdk/` | LCD 界面 SDK（emoji GIF + 触控,ui_lite + wms_client） | **改这里** |
| `applications/agent_test/app_test/` | 三段式语音 agent 应用,产物即**开机自启的 /bin/agent_test** | **改这里** |
| `Core_SDK/SDK/` | **内核重链 SDK**:build_kernel.sh + obj/ 1230 个官方 .o + ld 脚本 + sysroot + mpp/soc 库 + liteos_baseline 验收基准 | 不动（用法 §7） |
| `deps/` | 依赖仓**符号链接**（浏览用,BUILD.gn 不引用） | 不动;移植时可不带 |

组件边界:pca9685_sdk、wake_sdk 完全自包含（无包外路径依赖）,可单独开源交付;
app_test/BUILD.gn 通过 `//kernel/liteos_m/.../agent_test/<组件>`
标签引用其他 SDK 的 .a 库与头文件——**7 个组件必须平铺在同一 agent_test/ 下才能编译**。

⚠️ 各 SDK 目录里的 `bundle.json` 已改名为 `bundle.json.off`——**这是故意的**（防止被 kernel
子系统误扫描、与环境树 applications 壳重复声明 → LOAD 直接报错）。不要改回去;从上游拷新目录时
同理（§6.2）。组件声明只存在于顶层 `applications/` 壳（附录 A）。

**本包对环境树的硬依赖**（BUILD.gn 直接引用,缺哪个 gn 生成期/编译期即报错,按名补齐）:
`//device/soc/hisilicon/common/platform/agent`（内核侧 agent_core 源码,app_test 的 BUILD.gn
以 `agent_root` 直接把它的源码编进本包。**注意:这是本地定制目录——最小树环境自带;
完整系统树默认没有,须向维护者索取后原样放到该路径**）、
`//device/soc/hisilicon/hi3516dv300/sdk_liteos`、`//drivers/hdf_core/...`（头文件）、
`//foundation/arkui/ui_lite/frameworks`、
`//third_party/{bounds_checking_function,mbedtls,wpa_supplicant}`、
`//vendor/hisilicon/hispark_taurus/data/...`（背景图/语音素材）。
以上除 agent 外均为 OpenHarmony 标准仓,最小树与完整树都有。

## 3. 环境前提（一次性自检）

### 3.1 环境树形态（二选一,判定见 §1.1）
- **liteos_m_branch 最小系统树**（82 仓小系统 + `kernel/liteos_a_stub` 内核桩）:
  没有 liteos-a 源码是正常且必需的形态——不要试图补全内核源码（§10 禁忌 7）。
- **3516 完整系统树**（repo 全量,含 liteos_a 源码）:内核照常源码编译,本包用法完全相同;
  需补 device/soc agent 目录（§2/§4①）,并跳过 §3.3（树里一般已有 prebuilts）。

### 3.2 系统包与 hb
```bash
sudo apt update
sudo apt install -y bison ccache default-jdk flex gcc-arm-none-eabi genext2fs \
    libssl-dev libtinfo5 mtd-utils mtools ruby scons u-boot-tools zip python3-pip git
pip3 install ohos-build
hb --version    # 能打印即成功
```
建议树放在 WSL 文件系统内（如 `~/code/`）,不要放 `/mnt/c/`（IO 慢一个数量级）。

### 3.3 工具链 prebuilts（最小树需自备;完整树一般已有,可跳过本节）

**最小树自备大件,约 2.5G;环境件,不随源码分发**。完整树建树时已含 prebuilts（若 clang 版本
≠ 15.0.4,能编过,但不保证与基线逐字节一致）。

| 目录（相对树根） | 体量 | 内容 |
|---|---|---|
| `prebuilts/clang/ohos/linux-x86_64/llvm` | 2.5G | OHOS clang/clang++ 15.0.4（`arm-liteos-ohos`）、llvm-objcopy、libclang_rt.builtins.a（内核重链同用） |
| `prebuilts/build-tools/linux-x86` | 4M | gn、ninja |

**从哪拿（二选一）**:
1. 从维护者处整目录拷贝（同版本,推荐）;
2. 官方脚本 `python3 build/prebuilts_download.py`——拉到的是上游当前版,clang 若 ≠ 15.0.4
   能编过,但不保证与基线逐字节一致。

**放置**（首次搭建第一件事）:
```bash
cd <树根>
rm -f prebuilts     # 环境树里带的是悬空符号链接,先删
mkdir -p prebuilts/clang/ohos/linux-x86_64 prebuilts/build-tools
# llvm 目录     → prebuilts/clang/ohos/linux-x86_64/llvm
# gn/ninja 目录 → prebuilts/build-tools/linux-x86
```
Core_SDK 重链时按包位置上溯 6 级自动找到树根 prebuilts;若放别处,
独立重链用 `TOOLCHAIN=/path/to/llvm/bin ./build_kernel.sh` 覆盖（§7）。

自检:
```bash
ls <树根>/prebuilts/clang/ohos/linux-x86_64/llvm/bin/clang && \
ls <树根>/prebuilts/build-tools/linux-x86/bin/gn && echo "工具链 OK"
```

## 4. 移植步骤（把包挂进环境）

**包的唯一合法位置:`<树根>/kernel/liteos_m/components/embedded_smart`。**
applications 壳的 gn 引用（两种环境）、最小树的内核桩 stub_link.py 与 build_kernel.sh
找工具链的相对路径,全部按此位置写死,换位置/改名必挂。

### ① 放包（两种环境同一路径）
```bash
# A. 整套环境树随包一起分发:包已在位,本步跳过
# B. 只拿到包(目录或 zip):拷到合法位置
cp -r embedded_smart <树根>/kernel/liteos_m/components/
```
若包以 git 仓形式提供（如 kernel_liteos_m fork 的 `components/embedded_smart`）,
克隆后同样把该目录整体拷到位即可（deps/ 下的符号链接可不带,不影响编译）。

**完整树注意**:
- `kernel/liteos_m` 在完整树里是 repo 管理的真实仓,放入后本包只是其中一个**未跟踪目录**,
  不影响该仓原有内容;但**不要把本包提交/推送到上游 kernel_liteos_m 仓**（§10 禁忌 9）。
- 完整树默认没有 `device/soc/hisilicon/common/platform/agent/`（本包 app_test 直接编它的
  源码,§2）——向维护者索取后**原样放到该路径**,否则 gn 生成期报源文件缺失。

### ② 装 applications 壳（7 个 bundle.json）
先判断环境形态:
```bash
ls <树根>/applications/llm_sdk/bundle.json
```
- **存在** → 环境已带壳,本步跳过（可用附录 A 对照表核对是否齐全）;
- **不存在** → 按附录 A 的对照表 + 生成脚本,创建 7 个壳。

### ③ vendor 挂组件
`vendor/hisilicon/hispark_taurus/config.json` 的 `applications` 子系统 `components` 数组
需含 7 个组件（llm_sdk / agent_test / pca9685_sdk / key_sdk / ui_display_sdk / app_test /
wake_sdk）。环境已带则跳过;补法见附录 B。

### ④ （可选）开机自启 agent_test
`vendor/hisilicon/hispark_taurus/init_configs/init_liteos_a_3516dv300.cfg` 加
`"start agent_test"` 与对应服务块（附录 B）。不加也能编译,只是上电不自启。

### ⑤ 移植自检清单（两种环境通用）
```bash
cd <树根>
ls kernel/liteos_m/components/embedded_smart/Core_SDK/SDK/build_kernel.sh    # ① 包在位(完整)
ls applications/llm_sdk/bundle.json applications/agent_test/app_test/bundle.json  # ② 壳在位
grep -n '"component": "llm_sdk"' vendor/hisilicon/hispark_taurus/config.json # ③ 已挂产品
ls device/soc/hisilicon/common/platform/agent/BUILD.gn  # ④ 硬依赖在位(完整树默认没有,先索取)
```
四条全过 → 进 §5 编译。

## 5. 首次编译（三步）

```bash
cd <树根>

# ① 选产品（只需一次;结果存于 out/envargs.json）
hb set -p ipcamera_hispark_taurus

# ② 全量编译（约 10 分钟,含 ccache 后增量更快）
hb build

# ③ 末尾出现 "build success" 即成
```

内核来源两种环境不同:
- **最小树**:不走源码编译——编译中 `kernel/liteos_a_stub:liteos_a` 目标自动调用本包
  Core_SDK 重链,`OHOS_Image.bin` 恒为 6578176 字节;
- **完整树**:liteos_a 源码照常编译,`OHOS_Image.bin` 尺寸随树内源码/配置而定。

本包功能代码的落点两种环境相同:**rootfs 的 /bin**。

### 5.1 编译产物在哪（out/hispark_taurus/ipcamera_hispark_taurus/）

| 产物 | 路径 | 说明 |
|---|---|---|
| **OHOS_Image.bin**（~6.6M） | 同上目录 | 内核镜像 → 烧 kernel 分区（最小树:Core_SDK 重链产物;完整树:源码编译产物） |
| **rootfs_vfat.img**（~31M） | 同上 | 根文件系统 → 烧 rootfs 分区（功能程序在 /bin） |
| **userfs_vfat.img**（50M） | 同上 | 用户分区 → 烧 userfs 分区 |
| 内核 ELF/map、各组件中间产物 | 同目录及 obj/ | 调试用 |

### 5.2 验证功能组件已进镜像（可选）
```bash
mkdir -p /tmp/rf && mcopy -n -i out/hispark_taurus/ipcamera_hispark_taurus/rootfs_vfat.img ::/bin/* /tmp/rf/
ls /tmp/rf | grep -E 'agent_test|llm_ask|my_wake|wifi_cli|customer_test|llm_test|key_demo|pca_demo|ui_display|wifi_wpa'
```
开机自启服务是 agent_test（init.cfg: `"start agent_test"` → `/bin/agent_test`）。

## 6. 功能开发（日常循环）

### 6.1 改现有功能
```bash
# 1. 直接改本包源码/BUILD.gn（单一源,无需同步）
vi kernel/liteos_m/components/embedded_smart/applications/agent_test/llm_sdk/llm_client.c

# 2. 增量编译（自动重出三镜像,通常 1~3 分钟）
hb build

# 3. 烧 rootfs（仅用户态改动）或全量三镜像,上板验证
```
只验证编译不出镜像: `hb build -T <gn 目标名>`（**是 BUILD.gn 里的 group 名,不是组件名**;
`hb tool --ls` 本树无输出,不可用）:

| SDK | -T 目标名 |
|---|---|
| llm_sdk | `llm_sdk_group` |
| key_sdk | `key_group` |
| pca9685_sdk | `pca9685_group` |
| ui_display_sdk | `ui_display_group` |
| wake_sdk | `wake_group` |
| app_test（开机自启 agent_test） | `agent_test_group` |
| llm_stream（流式库,随 app_test 自动编） | `llmclient_stream`（source_set,一般不需单编） |

### 6.2 LLM 流式问答（v1.3 llm_stream,已集成）

**架构**:`llm_stream/` 提供 `llm_chat_stream()`(SSE 流式,回调逐 token 打印,
单条消息上限 1KB)与 `llm_chat_raw()`(非流式,body 上限 3072B,返回原始响应)。
app_test 的问答入口 `chat_dispatch` 双通道自动分发:≤1KB 走流式打字机,超限走 raw 通道
（agent 四行长提示词场景,prompt 实测约 2.3KB < 3072B 预算）。

**上板验证**（串口 115200,进入 agent_test 控制台后）:
```
ip                          ← WiFi 在线
ask 请用300字介绍一下你自己   ← 正文逐字打字机冒出,收尾 [llm] 完成 N 字, 耗时 Xs = 流式通道
```
判别:收尾打 `完成 N 字` = 流式;打 `云端应答` + 整段一次出 = raw 非流式（>1KB 问题的预期行为）。
llm_test(customer_test 同)的 `gw chat`/`gw direct` 亦走流式。

**独立编译脚本**（交付验收用,产物不进镜像,GN 构建不依赖）:
```bash
cd <包内>/llm_sdk
bash build_llmclient.sh     # 先建流式库 → ../llm_stream/{libllmclient.a,.so}
bash build_llm_test.sh      # 链出 llm_test
bash build_customer.sh      # 链出 customer_test
```

### 6.3 新增一个组件（三步）
1. **放代码**:`kernel/liteos_m/components/embedded_smart/applications/agent_test/my_sdk/`
   （源码 + BUILD.gn,定义一个 group,如 `my_group`）。
   ⚠️ 新目录里**不要自带 `bundle.json`**（从上游拷 SDK 时常见）:会被 kernel 子系统误扫,
   与 applications 壳重复声明 → LOAD 直接报错。上游带的请改名 `bundle.json.off`。
2. **加壳**:`applications/my_sdk/bundle.json`,照抄附录 A 一键脚本里任一现有壳,
   改三处:name、segment.destPath（指到包内新目录）、sub_component（`//kernel/liteos_m/components/embedded_smart/applications/agent_test/my_sdk:my_group`）。
3. **挂产品**:`vendor/hisilicon/hispark_taurus/config.json` 的 applications 组件数组加
   `{"component": "my_sdk", "features": []}`。

然后 `hb build`。

## 7. 内核机制（按环境二选一）

### 7.1 最小树:Core_SDK 重链（无 liteos-a 源码）

- 链接输入 = 包内 `Core_SDK/SDK/obj/` 官方 1230 个 .o（顺序见 `link_inputs.txt`）+
  HiSilicon 预编译库（mpp/媒体、spinor/mmc/wifi、watchdog 等）,链接命令逐参数复现官方 gn,
  产物与官方镜像**逐字节一致**（验收: `cmp OHOS_Image_new liteos_baseline` 无输出）。
- 独立使用（不经 hb,调试内核侧改动时）:
```bash
cd <树根>/kernel/liteos_m/components/embedded_smart/Core_SDK/SDK
./build_kernel.sh                                  # 纯重链 → OHOS_Image_new(.bin)
./build_kernel.sh my_feature.o                     # 追加自编 .o（clang 旗标见 编译命令模板.txt）
./build_kernel.sh -x '*los_syscall*' my_los_syscall.o   # 剔除官方 .o + 换自己的实现
./build_kernel.sh -o my_image my_a.o               # 自定义输出名
```
⚠️ 链接带 `-Wl,--gc-sections`（与官方一致）:**没被任何已有代码引用的函数会被裁掉**。
新增代码要挂到可达路径（改 syscall 表、或替换调用点所在 .o 引用它）;
若 ELF 变大但 .bin 不变、或符号消失,就是被 gc 回收了,
用 `llvm-nm OHOS_Image_new | grep 你的符号` 排查。
- 想让自编 .o 进 **hb 出的镜像**:把目标加进 `SDK/link_inputs.txt`,交给桩在 hb build 时重链;
  换内核版本 → 用新版 Core_SDK 整包替换 `embedded_smart/Core_SDK/`。
- hb 产物与 Core_SDK 独立产物同源同款（6578176 字节）。

### 7.2 完整树:内核源码编译（不用 Core_SDK）

- liteos_a 源码在 `<树根>/kernel/liteos_a/`,按 OpenHarmony 常规方式修改源码/内核配置后
  `hb build` 即可——**不经过 Core_SDK、不涉及 link_inputs.txt**;
- 本包各组件是纯用户态,内核怎么改/重编都不需要动本包;反之改本包也不用重编内核
  （只烧 rootfs,§8）;
- 包里的 `Core_SDK/` 在完整树中**闲置**:仅作独立重链工具与官方基线回退镜像留存,可不删;
- 自编内核与官方基线不再逐字节一致属正常现象（回退基线说明见 §8）。

## 10. 禁忌（踩过的坑,勿重蹈）

1. **不要跑 `repo sync`**:vendor 带定制会报未提交错误,整树再同步会把本地散装目录搞乱。
   拉上游更新找维护者评估。
2. **不要删 `out/` 除非准备重来**（删了要重新 `hb set`）。
3. **不要把本包里的 `bundle.json.off` 改回 `bundle.json`**（被 kernel 子系统误扫,LOAD 直接报错）。
4. **不要动 `.repo/local_manifests/`**（keep_liteos_m.xml 按固定 SHA 保住工作区）。
5. **不要用 git checkout / repo 覆盖二进制**:树内 236 个 `.a/.so` 是从 LFS 指针替换成的真实文件,
   被指针覆盖后链接会报 `unknown directive: version`。
6. 长任务（首次全量编译）请在**前台**跑;WSL 后台进程会被会话回收杀掉。
7. **（最小树）不要"补回"精简掉的源码**:勿用 repo/git 恢复 liteos_a 全量源码（破坏 Core_SDK
   链接流程）;勿删 `kernel/linux/linux-5.10/` 里的 `scripts/`、`include/`、`arch/arm/tools`
   （musl headers_install 必需,缺一个全树编译必挂）。
8. **不要移动/改名本包路径,不要把 Core_SDK 拆出包外单独存放**（§4 的路径约定是全局写死的）。
9. **（完整树）不要把本包提交/推送到上游 kernel_liteos_m 仓**:它在完整树里是
   `kernel/liteos_m` 仓内的未跟踪目录;对该仓做 repo sync / git pull / clean 前,
   先把 `components/embedded_smart` 整体备份,操作完再放回。
