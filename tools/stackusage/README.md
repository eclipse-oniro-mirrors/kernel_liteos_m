# stackusage: Static Stack Usage Analyzer

stackusage parses the disassembly of ARM (Thumb/Thumb-2) and RISC-V
(RV32IMAC, Nuclei Zc extension) images and statically computes the
**peak stack usage of task/interrupt call chains**. Use it to:

- Provide a quantitative basis for task stack sizing
  (the `stackSize` argument of `LOS_TaskCreate`);
- Evaluate interrupt stack sizing;
- Catch deep call chains and recursion—stack overflow risks—at build
  time instead of chasing memory corruption at run time.

The tool is implemented with the Python standard library only:
no installation, no third-party dependencies, CI-friendly.

## Requirements

| Item | Requirement |
|---|---|
| Python | 3.6 or later |
| Disassembly file | Generated by the objdump of the toolchain matching the target architecture (see below) |

```bash
# Basic (addresses only; all estimation features available)
<toolchain->objdump -d OHOS_Image > OHOS_Image.asm

# Recommended (additionally enables -m 1/2 source location; requires -g)
<toolchain->objdump -d -l -S OHOS_Image > OHOS_Image.asm
```

Here `<toolchain->` is the prefix of the target toolchain, for example
`arm-none-eabi-` or `riscv32-unknown-elf-`.

Notes:

- The architecture is auto-detected from the file header, so `--arch`
  is normally unnecessary;
- The tool can be run from any directory; outputs (`cfg/config.ini`,
  `out/funcstack.json`) are created in the current working directory
  and never touch the tool directory.

## Quick Start

```bash
# 1) Full scan: rank all task entries by peak stack (results in JSON)
python3 stackusage.py --asm OHOS_Image.asm -j

# 2) Single entry: peak value and call tree of one task
python3 stackusage.py --asm OHOS_Image.asm -sp -t OsIdleTask -out

# 3) Interrupt stack: exception/interrupt paths
#    (configure cfg/config.ini first, see below)
python3 stackusage.py --asm OHOS_Image.asm -irq
```

## Command-Line Options

```
Required:
  --asm <file>       Path to the disassembly file

Optional:
  --arch <arch>      arm | riscv (auto-detected from the file header)
  -t FuncA,FuncB     Task entry function names (comma-separated)
  -sp                Single-point mode (with -t; analyze only the given entries)
  -r N               Recursion depth: recursive functions counted as N
                     frames in total (default 1, must be >= 1)
  -out               Print the results table and call trees to the terminal
  -j                 Write JSON to ./out/funcstack.json (for tooling)
  -L N               Call tree filter: show nodes with max_size >= N
  -l N               Call tree filter: show nodes with local_size >= N
  -m N               0=addresses only (default) 1=source line
                     2=source line + function-pointer variable name
  -irq               Interrupt stack mode (mutually exclusive with -sp/-t)
  --config <path>    Path to config.ini (default ./cfg/config.ini)
```

Option combinations:

| Combination | Behavior |
|---|---|
| `-sp` + `-t` | Single-point mode; the results table is printed by default |
| Without `-sp` | Full-scan mode: entries = all functions never called; table/trees printed only with `-out` (warnings + statistics by default) |
| `-out` + `-j` | Can be combined: terminal + JSON output |
| `-L`/`-l` | Affect only the `-out` call trees (AND intersection); JSON and table unaffected |
| `-irq` with `-sp`/`-t` | Mutually exclusive; combining them exits with an error |

## Output Reference

The terminal output consists of 5 sections (blank-line separated):
**recursion warnings → function-pointer warnings → results table →
call trees → statistics**.

### Warnings

```
[WARNING][Recursive function]:        <- recursion cycle; value depends on -r
<LOS_MemFree> -> <OsMemFree> -> <LOS_MemFree>

[WARNING]Miss_funcptr:<dns_call_found>:0x210032ce
                                      <- indirect call via register (BLX Rm); callee unknown statically
```

With `-m 1/2` the warning suffix becomes a source location
(e.g. `dns_call 46`).

### Results Table

```
Entry           PeakStack  CallChain
OsIdleTask      128        OsIdleTask>HalIrqHandler>HalIrqDispatch
OsHwiBhTask     64*Rec     OsHwiBhTask>OsHwiBhProcess*Rec
```

- `PeakStack` is in bytes; `*Rec` marks values affected by the
  recursion depth `-r`;
- `CallChain` is truncated after 10 hops.

### Call Trees (-out only)

```
function<OsIdleTask>:0x2102ec78 stack cost=2656
symbol task_entry   task_stack_max_cost local_cost
symbol+--<OsIdleTask>: 2656 32
|     symbol+--<__aeabi_uldivmod>: 48 16
```

One block per entry; `-L`/`-l` filter out small nodes so large trees
stay readable. `*Rec`/`*Tail`/`*Ignore` mark recursion, tail calls and
ignored functions respectively.

### JSON (-j only, `./out/funcstack.json`)

Keys are function addresses (hexadecimal strings); each function has
10 fields:

| Field | Description |
|---|---|
| FuncName / FuncAddr | Function name / address |
| LocalCost | Stack frame of the function itself (bytes) |
| MaxCost | Maximum path stack down to a leaf (bytes) |
| Called | Array of callee addresses |
| Location | Source location (`-m 1/2`, e.g. `los_task.c:821`) |
| IsCalled / IsRec / Depth | Called / recursive / depth flags |
| PtrVarName | Function-pointer variable name (`-m 2`: source variable; otherwise the register) |

With `-irq -j` the JSON additionally contains the reserved key
`Interrupt` (interrupt stack statistics).

## Indirect Call Completion (config.ini)

The target of an indirect call (`blx r3`) is a runtime value that
static analysis cannot enumerate. The tool **warns instead of
guessing** (no false silence, possibly extra warnings) and closes the
loop via manual completion:

```bash
# 1) First run: generate cfg/config.ini (one stub per unresolved site)
python3 stackusage.py --asm OHOS_Image.asm -j

# 2) Edit config.ini and complete the sites you care about:
#    Remarks_here:<function>:<address>:<target function>
#    Remarks_here:<function>:<target function>
#    Ignore_function:<function>        <- or ignore a function entirely

# 3) Re-run: the warning disappears; estimates follow the new edge
python3 stackusage.py --asm OHOS_Image.asm -j
```

Completed lines are preserved verbatim; the generated template part is
byte-identical across repeated runs with the same input (idempotent).

Interrupt stack mode requires the following entries in config.ini:

```
Interrupt_entry: HalExcHandleEntry          # interrupt entry function
Interrupt_isr: 3: TIM001_IRQHandler         # IRQ number -> ISR
```

## FAQ

**Q1: Hundreds of Miss_funcptr warnings—is that normal?**
Yes. Function tables and callback registrations are common in an
image; per-site warnings are by design. Complete the entries you care
about; the rest does not affect estimates of resolved code.

**Q2: How should I read values of recursive functions?**
`-r N` counts recursion as N frames in total (default 1). The actual
depth is a runtime property—set it according to your business logic;
affected values carry the `*Rec` marker.

**Q3: No source lines with `-m 1/2`?**
Source lines come from debug info (-g) plus objdump `-l`/`-S`. On
images built without -g, all three modes degrade to the same output
(expected behavior).

**Q4: `-irq` with `-t` fails?**
By design they are mutually exclusive: `-irq` only accounts for the
interrupt stack, whose entries come from config.ini rather than task
entry arguments.

**Q5: Do the numbers match real stack consumption exactly?**
They are static estimates with a conservative bias: stack operations
that cannot be resolved precisely are treated as unreleased (rather
overestimate than underestimate). Runtime behavior—interrupt nesting
depth, dynamic stack usage—is out of scope for static analysis.

**Q6: How do I verify my environment?**
Run a full scan on any image (`--asm xxx.asm -j`); if warnings,
statistics and `out/funcstack.json` come out, the environment is ready.

## Constraints and Limitations

1. **Indirect calls**: targets are unknown statically; they rely on
   manual completion via config.ini. Uncompleted sites produce
   warnings instead of guesses.
2. **Recursion depth**: `-r` is user-specified; the actual depth
   requires business judgment.
3. **Source location**: `-m 1/2` requires the image to be built with
   -g and disassembled with objdump `-l`/`-S`.
